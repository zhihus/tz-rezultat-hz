# Скрипты конвейера tz-rezultat-hz

Канон скриптов — `.zcode/skills/tz-rezultat-hz/scripts/`.
Маршрут и правила — SKILL.md скилла.

## Быстрый старт

```
python.exe tz_tool.py extract --folder <папка образцов> -o <папка версии>
python.exe tz_tool.py build   -o <папка версии>
python.exe tz_tool.py verify  <папка версии>/шаблон_ТЗ_1С.docx
```

Итоговые документы называются ТОЛЬКО по шаблонам из образцов
(spec.meta.file_name_pattern):
- бизнес-ТЗ: `Заказчик_ТЗ_{КОД}_V{ВЕРСИЯ}.docx`
  (напр. `Ромашка_ТЗ_ФР.000.00.00.0-47_V1.docx`);
- техническое ТЗ: `Приложение к ТЗ {КОД}_V{ВЕРСИЯ}.docx`
  (напр. `Приложение к ТЗ ФР.000.00.00.0-62_V9.docx`).
Имя НЕ придумывается ни из кода, ни «по смыслу»; «финал» добавляет
только пользователь. Раскладка файлов проекта — `check_layout.py`.

| Файл | Назначение |
|---|---|
| `extract_spec.py` | образец или пересечение всех образцов (`--folder`) → `spec.json` (разделы, таблицы, скриншоты, подфункции, нумерация, оформление) |
| `build_from_spec.py` | `spec.json` → шаблон DOCX (без захардкоженной структуры; плотность из спецификации; плейсхолдеры `[ИМЯ \| пример: …]`) |
| `verify_template.py` | проверка шаблона — гейт 1 (плейсхолдеры, нумерация, строки таблиц, плотность, сверка с образцами, preflight, рендер PNG; `--filled` для заполненного ТЗ) |
| `render_md.py` | этап 2: Markdown → DOCX на шаблоне (`--figs`, `--set`, подписи по has_caption, нормализатор «Источников») |
| `final_gate.py` | E-53: единый финальный гейт — карта + линт + гейты DOCX + язык документа + сквозные F1–F11 |
| `check_language.py` | язык проверки правописания документа (DOCX/PPTX): чужой язык (it-IT/en-US от образцов заказчика) или отсутствие языка → FAIL; `--fix --out <новый файл>` — исправить новой версией (на месте запрещено); конвейер зовёт `tz_common.set_language_ru` сам |
| `check_map.py` | E-51: гейт карты объектов тех-ТЗ (G7–G10) |
| `plan_sections.py` | E-55: план разделов по зависимостям (plan.md + plan.json) |
| `preflight.py` | E-49: Шаг 1 одним вызовом — окружение, Word COM, format-agent (разворачивает из рантайма), активный проект; плоский отчёт, модель читает |
| `find_samples.py` | E-49: поиск DOCX-кандидатов с правилами исключений (Шаг 3) |
| `init_project.py` | E-49: создание проекта + перенос образцов + projects.yaml, идемпотентно (п.12) |
| `check_layout.py` | раскладка файлов проектов (урок 2026-11-19): старые версии тз→кухни, итог кухня→тз, чужое корня→temp; FAIL + ДЕЙСТВИЕ для незнакомого; модель только запускает |
| `find_config.py` | E-49: рекурсивный поиск связки 1С; готовый отчёт при неудаче (E-38) |
| `lint_draft.py` | E-49: линт черновика ДО render_md (G1–G6, G11: глоссарий, «Типовой/Новый», роли, рисунки, пути конфигурации) |
| `gen_miniprofiles.py` | E-49: каркас минипрофилей из spec.json — модель заполняет «ФОРМУЛИРОВКИ» (E-37) |
| `tz_tool.py` | единая точка входа: `extract` / `build` / `verify` / `run` |
| `requirements.txt` | pinned-зависимости (воспроизводимые бинарники) |
| `build_binary.bat` / `build_binary.sh` | сборка one-file бинарника (Nuitka `--onefile`) |
