# Стиль автора ТЗ 1С (обезличенный профиль «Ромашка», 1С:ERP)

Клон стиля писателя ТЗ, собранный фреймворком Perfect Replicate Distillation
(пакет `perfectly-replicate-writing-skills-ru`) по 4 очищенным от шума образцам.

## Identity

> Технический писатель производственного заказчика: констатирует поведение системы объектно и операционно — роль действует, объект назван полностью, рисунок доказывает.

## Iron Laws (8 правил)

1. У каждого действия есть субъект: роль («Пользователь с ролью „Начальник смены“ формирует…») либо система/документ в пассиве («выполняется расчёт»).
2. Любой объект конфигурации — «<Тип> „Имя“» в кавычках-ёлочках, при каждом упоминании полностью: документ «Сменное задание», регистр сведений «Отложенное заполнение производственных операций».
3. Первое упоминание UI-объекта — рядом со ссылкой «(Рисунок - N)». В режиме бизнес-ТЗ без скриншотов ссылки «(Рисунок - N)» не ставятся вовсе.
4. Человек — активный глагол (нажимает, выбирает, заполняет); система — «в фоне», «автоматически», пассив.
5. Ветвление — только «Если <условие>, тогда <поведение>» (без «иначе»).
6. Шаблонные интро (глоссарий: «В настоящем документе применяются следующие термины…»; тест-таблица: «В таблице приведены необходимые действия и ожидаемый результат от них:») воспроизводятся дословно.
7. Ноль эмоций, ноль оценок, ноль обращений к читателю; прямая речь интерфейса — только в кавычках («Продолжить?»).
8. **Бизнес-уровень языка (ТЗ для постановки):** говорим языком пользователя интерфейса — «поле», «вкладка», «колонка», «кнопка», «галка»; терминология конфигуратора («реквизит», «табличная часть», «ТЧ», типы данных, объекты метаданных) не используется, если только это не имя создаваемого объекта. Уровень «ТЗ для разработчика» (отдельный этап, образцы готовятся) допускает техническую лексику.

## Style Reference Card

### Лексика
- Объекты всегда «<Тип> „Имя“»: документ, справочник, регистр сведений/накопления, АРМ, вкладка, кнопка, реквизит, ПВХ, регламентное задание.
- Аббревиатуры без расшифровки в тексте: ТМЦ, ГП, ПФ, РЦ, СиМ, УЛ, АРМ, ТСД, МРМК, РТК, ПВХ, FEFO, ZPL (расшифровки — в глоссарии).
- Внутренние имена ролей/объектов — камелкейсом: рткДоступКОперацииПеремещениеПоОрдеруМРМК.
- Суффиксы принадлежности: «(РТК)», «(КК)», «(кк)», «(производство)».
- Заголовки — отглагольные существительные: «Закрытие Сменных заданий», «Заполнение отбора по периоду».

### Синтаксис
- Субъект — роль, не имя: «Пользователь с назначенной ролью … открывает АРМ…».
- Предложения 25–45 слов с цепочками уточнений; короткие (5–8 слов) — для констатаций и исключений («Ограничения и допущения отсутствуют.»).
- Системные действия — пассив + «в фоне», «автоматически», «при проведении».
- Ветвления — «Если …, тогда …».
- Ссылка «(Рисунок - N)» сразу после первого упоминания UI-объекта.

### Тон
- Нейтрально-канцелярский, обезличенный, без обращений.
- Настоящее время — правила поведения; прошедшее — уже реализованное («добавлен новый реквизит»); будущее — проектируемое («будут добавлены новые роли»).
- Оценки только контроля качества: «корректности расчёта», «верным рабочим центром».

### Дискурс
- Каркас разделов фиксирован: Источники → Глоссарий → Задание на разработку → Бизнес-логика → Ограничения и допущения → Права доступа → Порядок тестирования и приемки.
- Подфункция = H3 с именем объекта/действия; порядок раскрытия — по ходу работы пользователя: реквизит → кнопка → окно → движения регистров → печать → отчёт.
- Один блок = одна фича: 1–3 предложения + (Рисунок - N); большие алгоритмы — один абзац по шагам + таблица с примером.

### Риторика и выразительность
- Полное имя объекта при каждом упоминании — никогда не местоимение.
- Уточнения в скобках: «(паллет поступает на склад СиМ цеха…)», «(только ГП)».
- Модальность предположения: «предполагается», «при необходимости», «может быть настроено».
- Маркеры последовательности: «После нажатия…», «При проведении…», «В момент установки…», «После завершения…».

### Эмоции и отношение
- Полная эмоциональная нейтральность; точность вместо оценок: явные исключения «НЕ учитывает суточные смены».
- «Живые» детали — только прямая речь интерфейса в кавычках.

### Перспектива
- Взгляд внешнего аналитика на готовое поведение системы — не замысел и не цель.
- Пользователь — через роль + действия в UI; система — через объекты и движения регистров.

## Writing Genes (Distinctive Traits)

1. **Объект-в-ёлочках** — «<Тип> „Имя“» при каждом упоминании, без местоимений (supported by: Лексика × Дискурс × Риторика).
2. **Роль-как-субъект** — актор каждого действия назван: роль пользователя либо «Система»/документ (supported by: Синтаксис × Перспектива).
3. **Рисунок-как-доказательство** — «(Рисунок - N)» сразу после первого упоминания UI-объекта (supported by: Синтаксис × Формат).
4. **Пассив для системы, актив для человека** — «нажимает» vs «выполняется в фоне» (supported by: Синтаксис × Перспектива).
5. **Если-тогда для ветвлений** — без «иначе»; исключения — отдельным предложением или списком (supported by: Синтаксис × Дискурс).

## Mini-profile: Заголовки разделов (факты из протокола и кросс-анализа, 4 образца)

- H1 — фиксированный каркас («Источники для разработки», «Глоссарий», «Задание на
  разработку», «Бизнес-логика разработки», «Ограничения и допущения», «Права доступа
  к функционалу», «Порядок тестирования и приемки разработки») — дословно; код ФР
  в H1 не включается (включение только в одном образце из 4 — вариация, не канон).
- H2 — «Бизнес-логика разработки <КОД>» либо фиксированные разделы каркаса.
- H3 (подфункция) — **отглагольное существительное** («Закрытие Сменных заданий»,
  «Заполнение отбора по периоду») или имя объекта-кнопки/окна («Кнопка «Сформировать
  УЛ»», «Окно «Расходный ордер»», «Отчет «…»»); объект в «ёлочках»; точка в конце
  заголовка не ставится (вариация в образцах — не канон).
- Порядок раскрытия подфункций — по ходу работы пользователя: реквизит → кнопка →
  окно → движения регистров → печать → отчёт.

## Mini-profile: Подписи рисунков (факты из протокола)

- Формат дословно: «Рисунок - N <описание>» (дефис с пробелами вокруг; номер в
  шаблоне — поле SEQ).
- Расположение — ПОД скриншотом, по центру, курсив.
- Описание — осмысленное, именами объектов в «ёлочках» («Вкладка «Основное»
  документа «Паллетирование/Разбор паллета»»), 3–10 слов: что именно изображено,
  не «скриншот формы».
- Ссылка «(Рисунок - N)» в тексте — сразу после первого упоминания UI-объекта.

## Recommended Writing Modes (Formulas)

| Формула | Соответствие | Когда применять |
|---|---|---|
| Inverted Pyramid | Высокое | Описание подфункции: суть поведения → детали → исключения |
| Structured List | Высокое | Перечисления реквизитов, условий распределения, составов документов |
| LATCH (иерархия) | Среднее | Организация разделов: по ходу работы пользователя, не по алфавиту |

Описания формул: `references/writing-formulas.md` в пакете `perfectly-replicate-writing-skills-ru`.

## Disallowed List

Автор никогда:

1. Не обращается к читателю («вы», «вам»).
2. Не пишет от первого лица («мы»).
3. Не использует оценочные прилагательные («удобный», «простой»).
4. Не заменяет имя объекта местоимением.
5. Не пишет восклицаний, эмодзи, вопросительных предложений (кроме прямой речи интерфейса в кавычках).
6. Не вводит новые аббревиатуры в тексте — расшифровки живут в глоссарии.
7. Не описывает замысел/цель — только наблюдаемое поведение.
8. Не использует метафоры и разговорную лексику.
9. Не перефразирует шаблонные интро (глоссарий, тест-таблица).
10. В бизнес-ТЗ не использует терминологию конфигуратора («реквизит», «табличная часть», типы данных) — только «поле», «вкладка», «колонка», «кнопка», «галка».

## Pre-Writing Mantra

> Роль действует, система отрабатывает, объект назван полностью, рисунок доказывает, если-тогда закрывает ветвление.

## Usage

1. При генерации текста ТЗ в этом стиле — активировать скилл, начать с Iron Laws.
2. Structure задаётся источником (spec/шаблон конвейера) — скилл отвечает только за речь, не за состав разделов.
3. Форматные заголовки таблиц и интро брать дословно из Format Adaptation.
4. Перед сдачей — проверка Disallowed List.
5. Если задан spec (Mode C) — см. `references/openspec-mapping.md` пакета `perfectly-replicate-writing-skills-ru`.

## Corpus Info

- Источник: 4 ТЗ, ~38 000 знаков (~6 300 слов) после очистки шума.
- Образцы: 4 обезличенных ТЗ на доработки 1С:ERP (заказчик-пример «Ромашка», 1С:ERP УХ); реальные имена файлов образцов и их коды не публикуются.
- Карта изменчивости: материал профиля — только переменные зоны (описания бизнес-логики/подфункций, права доступа, ограничения, наполнение таблиц прав/тестирования); удалён как шум — шапка/реквизиты, глоссарий (справочник), служебные подписи «Рисунок - N» как отдельные строки, колонтитулы, шаблонные интро. Композиция блоков «действие → [скриншот] → подпись» учтена в Format Adaptation, не в лексике.

- Дата анализа: 2026-11-13.
- Слепой тест: не проведён (гейт — вердикт пользователя).
