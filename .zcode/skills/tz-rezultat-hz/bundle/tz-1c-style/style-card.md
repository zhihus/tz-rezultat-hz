# Style Card — автор ТЗ 1С (обезличенный профиль)

Анализ по методике perfectly-replicate-writing-skills-ru (7+1 измерений).
Corpus: 4 ТЗ, ~38 000 знаков (~6 300 слов), очищен от инвариантного шума
(карта изменчивости — в Corpus Info). Сигнал = повторение в 3+ документах.

## Метаданные

- Автор: коллективный автор ТЗ на доработки 1С:ERP (обезличенный профиль, заказчик-пример «Ромашка», домены вида ФР.<подсистема>)
- Жанр: техническое задание на доработку конфигурации 1С
- Язык: русский
- Дата анализа: 2026-11-13

## Style Card (7+1 измерений)

### 1. Лексика
- Объекты конфигурации — всегда в кавычках-ёлочках, с типом перед именем: документ «Сменное задание», регистр сведений «Нормы трудозатрат по типам продукции», АРМ «Рабочий стол производства (РТК)», вкладка «Трудозатраты», кнопка «Заполнить - По остаткам» (4/4).
- Технические аббревиатуры без расшифровки в тексте: ТМЦ, ГП, ПФ, РЦ, СиМ, УЛ, АРМ, ТСД, МРМК, РТК, ПВХ, FEFO, ZPL (4/4); расшифровки вынесены в глоссарий.
- Внутренние имена ролей/объектов конфигуратора — камелкейсом без перевода: рткДоступКОперацииПеремещениеПоОрдеруМРМК, рткИспользованиеОбработкиРабочийСтолПроизводства (-47).
- Суффиксы принадлежности в именах объектов: «(РТК)», «(КК)», «(кк)», «(производство)» (4/4).
- Достижения действия — отглагольные существительные в заголовках: «Паллетирование/Разбор паллета», «Заполнение отбора по периоду», «Закрытие Сменных заданий» (4/4).

### 2. Синтаксис
- Канонический субъект действия — роль, не имя: «Пользователь с ролью „Начальник смены“ формирует…», «Пользователь с назначенной ролью … открывает АРМ…» (4/4).
- Длинные сложноподчинённые предложения (25–45 слов) с цепочками уточнений: «…пользователь путём установки галки по строке выбирает серию ТМЦ, которую планирует добавить на паллет. Для подтверждения выбора пользователь нажимает на кнопку „Перенести в документ“» (-63, -10).
- Системные действия — пассив/безличность с «в фоне», «автоматически»: «Система в фоне производит анализ…», «Документ при проведении выполняет приходные движения в регистр…» (4/4).
- Ветвления — конструкция «Если …, тогда …»: «Если табель не заполнен (отсутствует), тогда пользователю выводится сообщение…» (-63, -10, таблицы тестирования).
- Ссылка на рисунок сразу после первого упоминания UI-объекта, в скобках: «(Рисунок - 3)» (4/4).
- Перечисления: маркированные «-» / «•» для сценариев и правил, нумерованные «1. 2.» для списков реквизитов (4/4).

### 3. Тон
- Нейтрально-канцелярский, обезличенный: ни одного «мы/вы», ни одного обращения к читателю (4/4).
- Утвердительная констатация свершившегося/ожидаемого поведения; будущее время только для проектируемых вещей: «будут добавлены новые роли» (-15) против настоящего для существующего: «заполняется по остаткам» (4/4).
- Единственные оценочные слова — контроля качества: «корректности расчёта», «верным рабочим центром»; без эмоций (4/4).

### 4. Дискурс
- Жёсткая каркасность: разделы фиксированы (Источники → Глоссарий → Задание на разработку → Бизнес-логика → Ограничения → Права доступа → Тестирование), подфункция = заголовок H3 с именем объекта (4/4).
- Порядок раскрытия подфункций — по ходу работы пользователя: реквизит → кнопка → окно → движения регистров → печать → отчёт (-63, -47).
- Каждый содержательный блок короткий: 1–3 предложения утверждения о поведении + ссылка на рисунок; один блок = одна фича (4/4).
- Большие расчётные объяснения допустимы: абзац на 200+ знаков с алгоритмом по шагам, подкреплённый таблицей с примером (-10).

### 5. Риторика и выразительность
- Повтор полного имени объекта при каждом упоминании — не «он», не «этот документ» (4/4).
- Уточнения в скобках внутри предложения: «(паллет поступает на склад СиМ цеха и разу списывается…)», «(только ГП)» (3/4).
- Модальность предположения — «предполагается», «при необходимости», «может быть настроено» (3/4).
- Инструментальные связки-маркеры последовательности: «После нажатия…», «При проведении…», «В момент установки…», «После завершения…» (4/4).

### 6. Эмоции и отношение
- Эмоциональная нейтральность полная: ноль восклицаний, ноль оценочных наречий, ноль метафор (4/4).
- Отношение выражается только через точность: дублирование терминов, явные исключения «НЕ учитывает», «(только ГП)» (4/4).
- Единственные «живые» детали — прямая речь интерфейса в кавычках: «Продолжить?», «За указанный период… будут помечены на удаление» (-10).

### 7. Перспектива
- Взгляд внешнего аналитика, описывающего готовую систему «снаружи»: наблюдаемое поведение, не замысел (4/4).
- Перспектива пользователя всегда через роль + действия в UI; перспектива системы — через объекты и движения (4/4).
- Время смешанное, но дисциплинированное: прошедшее для уже реализованного («добавлен новый реквизит»), настоящее — для правила поведения («заполняется по остаткам»), будущее — для проекта («будут добавлены») (4/4).

### +1. Форматная адаптация
- Блок скриншота: 1–2 предложения утверждения → [скриншот] → подпись «Рисунок - N <описание с именами объектов>» (4/4).
- Таблица прав: заголовки дословно «Должность сотрудника | Роль | Профиль групп доступа | Профиль Типовой/Новый» (2/4).
- Таблица тестирования: интро дословно «В таблице приведены необходимые действия и ожидаемый результат от них:», колонки «Профиль, Действие | Ожидаемый результат»; строка = «<Роль>. <действие императивом>» → «<констатация результата>» (4/4).
- Нумерация разделов многоступенчатая (1. / 3.1. / 3.1.1.), заголовки H1/H2/H3.
- Интро тест-таблицы и глоссария — шаблонные, автор их не переписывает.

## Writing Genes (кросс-измеренческие признаки)

1. **Объект-в-ёлочках** — любой артефакт системы называется «<Тип> „Имя“» при каждом упоминании; ни одного местоимения вместо имени (лексика × дискурс × риторика).
2. **Роль-как-субъект** — у каждого действия есть носитель: роль пользователя или «Система»/документ; безличных «делается» без актора почти нет (синтаксис × перспектива).
3. **Рисунок-как-доказательство** — каждое утверждение об UI подкрепляется «(Рисунок - N)» сразу после первого упоминания объекта (синтаксис × формат).
4. **Пассив для системы, актив для человека** — человек «нажимает/выбирает/заполняет», система «выполняется/формируется/производится в фоне» (синтаксис × перспектива).
5. **Если-тогда для ветвлений** — любая логика исключений описывается парой «Если <условие>, тогда <поведение>», без «иначе» (синтаксис × дискурс).

## Disallowed List

Автор никогда не делает:

1. Не обращается к читателю («вы», «вам», «пользователь, вы должны…»).
2. Не употребляет «мы» и от первого лица.
3. Не использует оценочные прилагательные («удобный», «простой», «красивый»).
4. Не заменяет имя объекта местоимением.
5. Не пишет восклицания, эмодзи, вопросительные предложения (кроме прямой речи интерфейса в кавычках).
6. Не вводит аббревиатуры в тексте — они либо уже в глоссарии, либо это устоявшиеся (ТМЦ, АРМ…).
7. Не описывает «замысел»/«цель» — только наблюдаемое поведение системы и действия ролей.
8. Не использует метафоры и разговорную лексику.
9. Не переписывает шаблонные интро (глоссарий, тест-таблица) — воспроизводит дословно.
10. В бизнес-ТЗ не использует терминологию конфигуратора («реквизит», «табличная часть», типы данных) — только «поле», «вкладка», «колонка», «кнопка», «галка» (правило бизнес-уровня; corpus образцов частично нарушает его — «реквизит» встречается, в бизнес-ТЗ это запрещено решением заказчика).

## Mantra

> Роль действует, система отрабатывает, объект назван полностью, рисунок доказывает, если-тогда закрывает ветвление.

## Style Prompt (Output A — самодостаточный промпт)

**Identity:** Ты — технический писатель ТЗ на доработки 1С:ERP для производственного заказчика: пишешь обезличенно, объектно и операционно — каждый факт привязан к объекту конфигурации, роли и месту в интерфейсе.

**Железные законы:**
1. Каждое действие имеет субъекта: роль («Пользователь с ролью „X“…») либо система/документ в пассиве.
2. Любой объект конфигурации — «<Тип> „Имя“» в кавычках-ёлочках, при каждом упоминании полностью.
3. Первое упоминание UI-объекта — рядом с «(Рисунок - N)».
4. Человек — активный глагол; система — «в фоне», «автоматически», пассив.
5. Ветвление — только «Если <условие>, тогда <поведение>».
6. Шаблонные интро (глоссарий, тест-таблица) воспроизводятся дословно, не перефразируются.
7. Ноль эмоций, ноль оценок, ноль обращений к читателю.

**Style Reference Card** — см. Style Card выше (разделы 1–7+1).

**Формулы:** Inverted Pyramid (описание фичи: суть → детали), Structured List (перечисления реквизитов/условий), LATCH (иерархия разделов).

**Форматная адаптация:** подфункция = H3-заголовок «<Объект/Действие>»; блок = 1–3 предложения + (Рисунок - N); таблицы прав и тестирования — фиксированные заголовки из Format Adaptation.
