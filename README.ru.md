# tz-rezultat-hz — скилл подготовки ТЗ для 1С

**Инструмент для агентской разработки технических заданий (ТЗ).**
Рассчитан на работу вместе с AI-агентом, который выполняет основную часть
процесса самостоятельно. English version — [`README.md`](README.md).

## Как это работает

Вы предоставляете материалы; агент:

- анализирует то, что вы предоставили;
- изучает образцы ТЗ и использует их как ориентир;
- задаёт вопросы, если исходных данных не хватает;
- формирует структуру и содержание технического задания;
- выполняет проверки и дорабатывает результат.

## Роль пользователя

Вы даёте то, чем агент не может располагать самостоятельно: образцы и
примеры ТЗ, ответы на уточняющие вопросы, описание бизнес-процессов и
требований — другие исходные данные и экспертную информацию.

Основную аналитическую и документальную работу вручную выполнять не нужно:
её выполняет агент. Вы подключаетесь там, где необходимы ваши знания,
решения и подтверждение результата.

## Чего инструмент не делает

- Он **не** работает полностью автономно: процесс нельзя завершить без
  ваших ответов и подтверждения результата.
- Агент **не** знает специфику вашего предприятия сам по себе: особенности
  конфигурации, локальные правила и исключения берутся только из ваших
  исходных данных.
- Качество результата напрямую зависит от предоставленных вами образцов,
  описаний и ответов: скудные исходные данные дают скудное ТЗ.

> **Поддерживаемые платформы: Windows и Linux.** Эта версия устанавливается
> и работает на Windows (`win-x64`) и на Linux (`linux-x64`). Обе —
> полноправные: один и тот же пиннутый рантайм, один и тот же полный
> комплект и одна и та же транзакционная установка (каталог-кандидат →
> валидация → замещение; прежний рабочий рантайм переносится в
> `.staging/previous-*`, не удаляется и восстанавливается при любом сбое).
> Другие платформы (arm64, macOS) не поддерживаются: гейт в `bootstrap.py`
> останавливает запуск до любых загрузок и изменений.

## Установка

Скилл — это просто папка. Скопируйте `.zcode/skills/tz-rezultat-hz/` в
каталог скиллов вашего агента, например:

```
~/.agents/skills/tz-rezultat-hz/
```

Python в репозитории не поставляется. При первом использовании агент
запускает точку входа платформы **без флага режима** — `bootstrap.ps1`
на Windows или `bash bootstrap.sh` на Linux: скрипт печатает перечень
компонентов **полного комплекта** — основного и рекомендуемого сценария —
с назначением каждого компонента и последствиями его отсутствия
(см. `components.ru.md`) и завершается, **ничего не скачивая**. После
вашего подтверждения тот же скрипт запускается в режиме полного комплекта:

```
bootstrap.ps1 -Full          # Windows
bash bootstrap.sh --full     # Linux
```

Затем он скачивает, сверяет с закреплёнными пинами (коммиты upstream +
контент-SHA-256) и устанавливает: пиннутый `python-build-standalone`,
зависимости Python (`scripts/requirements.txt`), пиннутый минимальный набор
`format-agent` и пиннутый скилл `grilling` — последние два из их официальных
upstream-коммитов. Повторные запуски проверяют уже установленные компоненты
и **не** перекачивают исправные. Если обязательный компонент не удаётся
скачать или сверить, установка останавливается с `[FAIL]`, а рантайм и
манифест остаются без изменений — успех никогда не имитируется.

`tz-1c-style` входит в этот репозиторий (`bundle/`, MIT);
`scripts/preflight.py` проверяет окружение и разворачивает его.

**Отказ от `grilling` означает неполноценную аналитику.** Самопроверка
Шага 2 («прожарка») становится недоступной, а непроверенные пробелы уходят
в ТЗ — это не нормальная работа. Установка без этого компонента возможна
только по явному отказу (`bootstrap.ps1 -NoGrilling`) и не предлагается как
равноценная альтернатива.

Дальнейшие проверки сохраняют различие сигналов (они не взаимозаменяемы):
комплект, заявленный **полным**, при отсутствующем или повреждённом
`grilling` даёт **`[FAIL]`** и должен быть восстановлен в полном режиме до
начала работы; только явно отклонённый комплект — или манифест прежнего
формата (schema 1, без сведений об установке), комплект которого
**неизвестен**, — даёт **`[WARN]`** и никогда не считается подтверждённой
полной установкой.

## Использование

Работа идёт через агента: опишите доработку 1С — скилл строит шаблон ТЗ и
заполняет его. Точка входа и пошаговый протокол — `SKILL.md`.

## Состав репозитория

- `README.md` / [`README.ru.md`](README.ru.md) — это описание (EN / RU).
- `.zcode/skills/tz-rezultat-hz/SKILL.md` — маршрут и правила скилла.
- `bootstrap.ps1` / `bootstrap.sh` / `bootstrap.py` — установка рантайма
  (Windows и Linux). `bootstrap.ps1` — точка входа для Windows,
  `bootstrap.sh` — для Linux; оба делегируют `bootstrap.py` и собирают
  транзакционно (каталог-кандидат → валидация → замещение).
- `components.ru.md` — перечень компонентов, печатаемый при первом запуске.
- `scripts/` — конвейер (извлечение, сборка, гейты, рендер).
- `references/` — модель документа и метод.
- `bundle/tz-1c-style/` — базовый слой тона (MIT).

## Документация

Технически конвейер такой: образцы ТЗ → `spec.json` → плотный шаблон DOCX →
два гейта (структурный + визуальный); этап 2 заполняет шаблон текстом
бизнес-ТЗ из описания доработки.

- Модель документа и метод разбора:
  [`references/document-model.ru.md`](.zcode/skills/tz-rezultat-hz/references/document-model.ru.md)
  (RU) и машиночитаемый каталог
  [`document-model.ru.yaml`](.zcode/skills/tz-rezultat-hz/references/document-model.ru.yaml).
- Мини-профили авторов:
  [`references/writer-profiles.ru.md`](.zcode/skills/tz-rezultat-hz/references/writer-profiles.ru.md).
- Процесс (для пользователя): [`docs/process-ru.md`](docs/process-ru.md) (RU).

Документация и генерируемые документы — на русском языке (проект выпускает
русские ТЗ для 1С).

## Зависимости

Всё устанавливается при первом использовании бутстрапом скилла и **не**
распространяется этим репозиторием: Python и библиотеки (python-docx,
PyMuPDF, lxml, pywin32), `format-agent` (пиннутый upstream-коммит) и
`grilling` (пиннутый upstream-коммит, MIT). Лицензии и происхождение —
[`THIRD-PARTY.md`](THIRD-PARTY.md).

## Разработка и публикация

Это самостоятельный проект. Новые задачи начинаются от актуальной `develop` в отдельных локальных и удалённых рабочих ветках, после проверки вливаются обратно в `develop`. Текущее содержимое `main` сохраняется без изменений; перенос туда возможен только по отдельному явному решению пользователя. Данные заказчиков и персональные данные публиковать запрещено. См. [правила границ проекта и публикации](docs/project-boundaries-and-publication.md) и [инструкции для агентов](AGENTS.md).
